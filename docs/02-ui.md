# 02. UI

## Model

The compositor owns the terminal and lays out panes. The primitives below are part of the protocol, not tied to a specific library: every renderer implements them identically.

## Primitives

- **Pane** — a surface: a named cell buffer (`wl_surface`). A plugin declares a surface; the compositor allocates a slot for it.
- **Site** — a layout slot (`xdg_toplevel`) that a pane binds to. Layouts are swappable, like tiling schemes in Sway.
- **Status bar** — a layer above everything (`layer-shell`): active model, token budgets, workflow state, plugin roster.
- **Focus / input routing** — input is delivered to the focused pane; a click moves focus, as in a window manager.
- **Damage tracking** — a pane marks changed regions (`invalidate`); the compositor redraws only those, not the whole screen.

## Shipping terminal window controls

The normal CLI currently uses Ink. Its **[Arrange] / Alt+w** mode exposes the
existing tiling tree directly: focus, directional moves, columns/rows, resizing,
fullscreen and workspaces. The dock identifies the mode and focused window;
ordinary typing resumes with **i**. Mode input cannot submit a draft or settle a
model question or permission request. **[Windows] / F2 / /windows** opens a
searchable inventory across workspaces and closed views, including the existing
main conversation. Opening a plugin entry uses its actual declared UI route.
Escape returns without changing the previous editor or its cursor.

See the [terminal controls](../packages/app/README.md#tiling-windows) for the full
key map, custom-editor bindings and form behavior. These shipping controls and
the experimental OpenTUI preview below have separate entry points and key maps.
The preview is not selected by launching the installed `compositor` binary.

## OpenTUI conversation prototype

Run `npm run opentui:preview` in a terminal from a source checkout with
Bun 1.4.4 and installed workspace dependencies. This opens a local preview
with two independent agent conversations, a workflows table and plugin management.
The demo starts a sample workflow and uses a deterministic local provider.
It stores state in a temporary directory for the life of the preview.

Main and Side start in two visible tiles. A pane's visibility and keyboard focus
are independent. The focused title and border identify the input destination.
Opening another pane splits the focused pane. All registered views remain
available from the top bar, including panes closed or moved to another workspace.
Below 70 terminal columns the focused pane fills the available area. Widening
the terminal restores the saved tree and ratios. The host uses the same binary
tiling manager as the Ink frontend. OpenTUI receives resolved rectangles and
focus, and keeps native widgets mounted while their bounds or visibility change.

| Control | Action |
| --- | --- |
| F2 / F3 | Open or focus Main / Side, switching to its workspace when already open |
| F4 / F5 | Open or focus Workflows / Plugins |
| F6 | Cycle the current workspace's panes, including collapsed panes |
| F7 | Change the nearest split orientation, or the next split direction when alone |
| F8 | Swap the nearest split's children |
| F9 | Zoom the focused tile, or restore the split |
| F10 | Close the focused pane; its top-bar button reopens it |
| Alt+Left / Alt+Right | Resize the focused pane's nearest split |
| Alt+H / J / K / L | Focus a pane to the left / below / above / right |
| Alt+Shift+H / J / K / L | Swap the focused pane with a directional neighbor |
| Alt+1…9 | Switch workspace |
| Alt+Shift+1…9 | Move the focused pane to a workspace and follow it |
| Mouse | Focus by clicking, drag a title to an edge or center, or drag a separator |

Dropping a title on a pane's edge creates a split; dropping it in the center
swaps the panes. Dropping on a workspace button moves it there. **Escape** cancels
a drag or resize. Window gestures temporarily suspend editor and approval keys.
Closing a pane hides its view. Its agent continues, and reopening restores the
same editor, unsent draft and in-process transcript.

1. In **Main**, submit `hold main` to keep a response streaming. Type a draft.
2. Press **F3** or click the Side title. Enter a message and submit with **Enter**
   or its **Send** button. **Ctrl+J** adds a newline. Both conversations keep
   independent drafts while focus moves. **Ctrl+Z** undoes a composer edit and
   **Ctrl+Y** redoes it, including after closing and reopening that pane.
3. Press **F4** for **Workflows**. Use **↑/↓** to select a row and **Enter** or
   a click to expand its details. Use F9 when a detail view needs more room.
4. In a ready conversation, submit `request write`. Review the tool, reason,
   path and arguments in the approval card. **PgUp/PgDn** scroll the details.
   **Alt+Y** allows this one call and **Alt+N** denies it. The buttons also
   work with the mouse. The composer keeps your draft while you review.
5. Move focus while an approval is pending. Each waiting chat shows an
   **Approval** badge. Approval shortcuts act only in the focused conversation.
   **Ctrl+C** closes the preview and declines outstanding requests.

Submit `request question`, `request custom` or `request questionnaire` in either
chat to exercise actual `ask_user` / `ask_questions` calls. A pending question
shows a badge and keeps the message draft available. **Alt+I** or **Edit answer**
switches between the draft and the answer editor. Selecting an option does not
submit it. Use **Alt+Enter** or **Submit** to send the complete answer; **Escape**
or Cancel cancels only the active input while in Answer mode. Invalid or missing
answers remain pending. Questionnaires support Back/Next and preserve earlier
choices, multiple selections and custom text.

Each conversation has its own FIFO of approval, question and form requests.
Closing a window preserves its pending request and input draft. Another chat or
Plugins remains usable while the requesting agent waits. **Ctrl+X** or Stop
interrupts the focused agent's foreground turn, including its question; it does
not answer a permission request. **Ctrl+C** closes the entire preview.

The trusted `/preview-form` command opens private **Preview settings** with
text, URL, password, select and toggle fields. **Alt+I** / Edit form opens its
editor, Tab moves between fields, and arrows or Enter change choices. Submit
with the named action button, **Alt+Enter**, or Enter after tabbing to that action;
Escape cancels in the form editor. This demo command declares a five-minute
hook timeout; expiry cancels its pending form through the supplied signal.
The password field renders a mask. Its value returns directly to the plugin,
without becoming a chat message or catalog event. The demonstration saves only
its length and SHA-256 hash as a test receipt and makes no remote connection.

Immediate commands declared by loaded plugins can run during a model turn or
pending question. Ordinary messages remain drafts until the agent is available.
A private form alone also permits an ordinary message from Draft mode: the
model can work while settings remain open. Foreground interruption preserves a
form whose separate user-operation signal is still live. Question answers are
model input, and never substitute for an execution permission decision.

The local approval example writes `main-note.txt` or `side-note.txt` inside
the temporary preview workspace. Each new write goes through the normal
tool permission policy.

Press **F5** for Plugins. **/** focuses the filter. Enter leaves the filter,
**↑/↓** selects a result, **←/→** selects an action and Enter runs it.
Buttons support mouse input. Remove requires a second explicit confirmation,
which Escape cancels. **R** or Refresh rereads the registered catalogs.

The preview registers an isolated local `preview-market` containing
`preview-notes`. Installation uses the real project extension store and leaves
the plugin inactive. Enable saves the selection. If Main is busy, activation
waits for it to become idle. The row distinguishes catalog, installed and loaded
versions, saved on/off selection and pending work. Update and removal retain
running package files until it is safe to apply them. Closing the preview
cancels its unapplied queued file operations. `/preview-note` in idle Main runs
the loaded plugin directly, records its version in plugin storage and posts a
notice, without asking the model.

The private `renderer-opentui` workspace owns rendering and native widgets.
The preview host translates core conversation events and plugin table updates
into its inputs. Selecting a workflow row returns that row's declared action
through the plugin's ordinary `ui.press` handler. The plugin owns expansion.
On a wide screen with negotiated Kitty graphics, the composer displays
the original idle or thinking Ghost. Set `AGENT_GRAPHICS=off` to hide it.

The host saves the full tree, ratios, open/closed panes, workspace and focus
through the application's layout store. The browser bench keeps an isolated
home across its **Restart session** action and verifies this restoration on disk
and on screen, including an empty workspace. The standalone preview still uses
temporary state for its lifetime. Layout restoration does not restore preview
transcripts or unsent drafts after the process exits.

The shipped terminal still uses Ink. This preview covers nested windows, native
composers, one-call permission decisions, workflow expansion and the local
plugin lifecycle plus native questions and private forms. The preview rejects
explicitly selected custom question/form controllers rather than replacing
them silently. Their adapter, full wire-protocol support, user placement-rule
controls, provider/settings flows, saved conversation recovery and release packaging are later migration
steps. [Migration plan](readiness.md#planned-opentui-migration--2026-11-13)

## Reference renderer implementation: Ink

React + Yoga flexbox: pane = `Box`, site = column/row, status bar = `Spacer` at the bottom. Scroll areas come out of the box in the new major Ink release: `overflow="hidden"` + `contentOffsetY` + the `useBoxMetrics` hook.

Starter layout:

```
┌──────────────────┬───────────────────────┐
│                  │  panes: agents        │
│  pane: session   │         tasks         │
│  (chat + stream) │         workflow      │
│                  ├───────────────────────┤
│                  │  pane: inspector      │
├──────────────────┴───────────────────────┤
│  status bar: model · tokens · plugins    │
└──────────────────────────────────────────┘
```

**Mouse:** the reference renderer parses SGR mouse sequences and forwards input
through the protocol. The compositor owns hit testing, focus, capture and
drag/resize. See [the terminal manual](../packages/app/README.md) for bindings
and [the visual bench](../tools/visual/README.md) for actual PTY verification.

The Ink renderer selects interactive repainting from its output stream's
`isTTY` flag. A real terminal continues to receive live frames with inherited
`CI` or `CONTINUOUS_INTEGRATION` flags; those flags do not turn the running
interface into an exit-only frame. A redirected renderer output stream retains
static final-frame output.

## The Claude Code lesson

Claude Code started on stock Ink and rewrote the render engine: the stock version allocates one object per terminal cell per frame (~24,000 objects at 200×120 every 16 ms) and diffs whole strings. Their fork: typed arrays instead of objects, double buffering, cell-level dirty tracking.

**Conclusion:** Ink's component model (React + Yoga) is permanent; the engine beneath it is a consumable that can be replaced without rewriting components. Hence the hard rule: the compositor consumes the core **only through the versioned protocol**, even when living in the same process with it. The seam matters more than the framework.

## Swappable renderers

One protocol — any number of implementations:

- **headless** — JSONL over stdio or a unix socket: tests, scripts, external tools;
- **TUI** — Ink (the reference);
- **web** — a future implementation could transport the same protocol over WebSocket; a web renderer is not currently shipped.

External tools (fzf, tmux, a custom dashboard) become clients of the compositor — the "netlink move" that no existing CLI agent has.
