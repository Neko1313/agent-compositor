# 02. UI

## Модель

Композитор владеет терминалом и раскладывает панели. Нижележащие примитивы — часть протокола, а не привязка к конкретной библиотеке: любой рендерер реализует их одинаково.

## Примитивы

- **Pane** — поверхность: именованный буфер ячеек (`wl_surface`). Плагин декларирует поверхность, композитор выделяет ей слот.
- **Site** — слот раскладки (`xdg_toplevel`): куда pane привязывается. Раскладки сменяемы, как тайловые схемы в Sway.
- **Status bar** — слой поверх всего (`layer-shell`): активная модель, бюджеты токенов, состояние workflow, состав плагинов.
- **Focus / input routing** — ввод доставляется pane с фокусом; клик переводит фокус, как в оконном менеджере.
- **Damage tracking** — pane помечает изменённые области (`invalidate`); композитор перерисовывает только их, а не весь экран.

## Реализация референс-рендерера: Ink

React + Yoga flexbox: pane = `Box`, сайт = колонка/строка, статус-бар = `Spacer` внизу. Скролл-области — из коробки в новой мажорной версии Ink: `overflow="hidden"` + `contentOffsetY` + хук `useBoxMetrics`.

Стартовая раскладка:

```
┌──────────────────┬───────────────────────┐
│                  │  panes: agents        │
│  pane: session   │         tasks         │
│  (chat + stream) │         workflow      │
│                  ├───────────────────────┤
│                  │  pane: inspector      │
├──────────────────┴───────────────────────┤
│  status bar: model · tokens · plugins    │
└──────────────────────────────────────────┘
```

**Мышь:** стоковый Ink события мыши не отдаёт — нужен тонкий слой парсинга SGR-последовательностей поверх `useStdin`. Альтернатива с мышью из коробки — openTUI; выбор откладываем до первой реальной потребности в кликах.

## Урок Claude Code

Claude Code начинал на стоковом Ink и переписал рендер-движок: стоковая версия аллоцирует объект на каждую ячейку терминала на каждый кадр (~24 000 объектов на 200×120 каждые 16 мс) и диффит строки целиком. Их форк: типизированные массивы вместо объектов, double buffering, dirty-трекинг ячеек.

**Вывод:** компонентная модель Ink (React + Yoga) — постоянна, движок под ней — расходник, который можно заменить, не переписывая компоненты. Поэтому жёсткое правило: композитор потребляет ядро **только через версионированный протокол**, даже живя с ним в одном процессе. Шов важнее фреймворка.

## Сменные рендереры

Один протокол — сколько угодно реализаций:

- **headless** — JSONL по stdio или unix-сокету: тесты, скрипты, внешние инструменты;
- **TUI** — Ink (референс);
- **web** — тот же протокол по WebSocket.

Внешние инструменты (fzf, tmux, собственный дашборд) становятся клиентами композитора — аналог «netlink-хода», которого нет ни у одного существующего CLI-агента.
